Included

No node_modules, generated production bundle, Git credentials/history, environment secrets, local runtime databases or customer records are included. Install dependencies and build the project to run it.

Stack

React 19.2.6 + TypeScript 5.9 + Tailwind CSS 4.2.1, with custom brand CSS. Next compatible App Router patterns implemented by Vinext 1.0 beta on Vite 8. Cloudflare Worker runtime, D1 SQLite storage and Drizzle schema/query support.
This is a Worker application, not a standard Next.js Node server. The package's next dependency does not make it deployable with next build. Preserve the supplied Vinext/Vite scripts. AWS or Vercel deployment requires explicit adaptation of the cloudflare:workers bindings, database and trusted identity layer.

Install and run

Requirements: Node.js >=22.13.0 and pnpm 11.25.0, an internet connection for package installation, and a modern browser.
```sh
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile
pnpm dev
```
If your Node installation does not include Corepack, install pnpm 11.25.0 through your approved package manager. Do not run the starter's install:ci script as a substitute for this pnpm lockfile.
The clean export defaults to the portable execution profile. Use the local URL printed by the server, normally http://localhost:5173. /apply works without member sign in. The hosted private Site can still require owner access independently of the application's enquiry form.
```sh
pnpm exec tsc --noEmit
pnpm build
node --experimental-strip-types scripts/check-loan-scenarios.mjs
node --experimental-strip-types scripts/check-enquiry-snapshot.mjs
node scripts/check-experience.mjs
pnpm start
```
The experience check expects a pnpm node_modules layout and a completed dist/server build. It starts its own temporary Miniflare database and applies migrations. It does not send emails or use production customer data. pnpm start runs the built Worker locally through Wrangler; it does not publish it.
For a separately running local built Worker, initialise its local D1 database if needed:
```sh
pnpm exec wrangler d1 execute DB --local --config dist/server/wrangler.json --file drizzle/0000_pale_moira_mactaggert.sql
pnpm exec wrangler d1 execute DB --local --config dist/server/wrangler.json --file drizzle/0001_clear_lorna_dane.sql
```
Run migrations only against the intended database. Do not repeatedly reapply CREATE TABLE migrations to an already initialised database. The generated config's placeholder database ID is for local development, not a real production database.

Current customer journeys

/apply starts with separate Personal borrowing and Business borrowing paths. Switching paths clears unsent entries, as the screen explains.
Consumer flow: loan selection, profile, income, home/residency, living expenses, assets, itemised liabilities, review and privacy. Amount range $10,000 to $500,000 and requested terms 2 to 7 years are enforced in the client and server. Product purposes change by loan type. Car enquiries include vehicle condition, seller, deposit and optional trade in. Relationship status enables joint enquiry selection for married/de facto applicants. Only the initiating person's information is collected; a second applicant needs separate follow up and consent.
Business flow: car/equipment/unsecured product and purpose, business details, owners/directors/trustees, business financial summary, review and privacy. Supports sole trader, company and trust, ABN, conditional ACN, trust/trustee details, optional business website and up to five owners/directors/trustees. ABN and ACN format checks are not register verification. Business website accepts http/https only; the server does not fetch submitted URLs. Director information requires authority confirmation.
Both paths submit to /api/loan-enquiries. Schema validation is in lib/loan-enquiry.ts. Consumer and business payloads are a discriminated union. The API converts validated information to bounded analyst notes and uses the contact enquiry persistence path. Success appears only after storage and displays a UUID reference. Anika's confirmation is scripted: it explains the dashboard is offline and a Lumio analyst will get in touch. No lender submission or credit check occurs.

Live Anika snapshot

The consumer form includes a browser local rules based sidebar. It annualises each income, estimates tax using 2026/27 Australian resident brackets and a simplified 2% Medicare allowance, calculates monthly net income, housing/debt commitments, a proposed repayment at an editable scenario rate, monthly buffer and separate net assets.
Tax residency must be explicitly confirmed; unknown tax treatment or incomplete figures pause the budget indication. FTB A/B default tax free, salary/self employment/rental default taxable and other benefits require confirmation. Tax deductions, offsets, Medicare reductions/exemptions, surcharge, HELP calculation, lender income shading and HEM are not calculated. These limitations are shown in the UI. An analyst must review actual income and taxation.
Green Surplus, amber Tight and red Shortfall describe the entered budget scenario, not lender serviceability or approval. The buffer threshold is an internal illustration: tight is zero to max($200,10% of estimated monthly net income); negative is shortfall. Mortgage repayments are counted through liabilities once. Assets never become income. Credit card limits are displayed separately and are not treated as debt balances or a lender assessment repayment. See docs/enquiry-snapshot-method.md and lib/enquiry-snapshot.ts for assumptions and verification sources.

Storage, access and security

Cloudflare binding DB is required. Tables applications (legacy owner isolated drafts) and contact_enquiries (submitted enquiry details in notes). No production data is exported. The current enquiries do not require member authentication; do not expose contact records through a public read endpoint.
Preserve the API's validation, bounded request size, same origin checks, honeypot, consent checks, rate limits and idempotency. No bank statement/ID/document upload is implemented. Sensitive enquiry fields are excluded from optional analytics, which are off by default and disabled on application/account routes.
app/chatgpt-auth.ts trusts Sites identity headers supplied by the hosting gateway. A standalone public deployment must strip untrusted identity headers and implement real verified sessions before enabling protected legacy APIs. Never trust identity strings supplied directly by clients. No staff enquiry inbox or role/permission system is included.

Hosting and deployment

Current hosting is the existing private Sites deployment on Cloudflare Workers/D1. The original .openai/hosting.json project ID is included for maintaining that Site only; it is not a credential and gives no account access. Do not overwrite another Site with it. A new Site requires a new identity and authorisation.
For a separate Cloudflare account: create the Worker and D1 database, bind DB, apply migrations, configure real Worker/database names and IDs and assets, then deploy the built output using reviewed deployment configuration. pnpm build generates dist/server/wrangler.json, Worker modules and dist/client assets. Never deploy its placeholder database ID. Review auth, rate limiting, storage retention, logging, permissions, domain/TLS and backups before exposing customer workflows.
For AWS or Vercel, port the Worker-specific storage/runtime/auth code and perform full integration testing. No AWS/Vercel infrastructure or production deployment is included. The frontend is React/Tailwind, but the backend is not a portable drop-in Lambda/Node service.
